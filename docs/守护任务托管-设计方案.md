# 托管任务（Task Hosting）：让 AI 写的守护程序住在 VPNTray 里

> 版本：方案稿（未实现）　日期：2026-11-14　基线：VPNTray 1.0.1
> 一句话：**AI 写的常驻脚本不该散落在计划任务和启动文件夹里，应该交给已经在开机自启、已经有日志、已经能被 AI 操作的那个程序来托管。**

---

## 1. 要解决的问题

现在 AI 帮用户写「一直跑」的东西（盯盘、爬数据、盯某个文件、给某个服务做探活、桥接某个本地端口），落地方式只有三种，都难看：

| 现状做法 | 问题 |
|---|---|
| 用户自己开个黑窗口跑 `python xx.py` | 关窗口就死；重启电脑就没了；看不到日志历史 |
| 注册 Windows 计划任务 / 丢启动文件夹 | 用户已明确否决（本项目原则：一切在软件内实现）；出错无人知；卸载残留 |
| 让 AI 写个 `nssm install` / 服务 | 需要管理员、需要额外工具、卸载难、杀软警觉 |

VPNTray 已经有了这件事需要的全部底座：**开机自启**、**托盘常驻**、**日志目录**、**AI 接口（40 工具）**、**模块化配置**。缺的只是一层「进程托管」。

---

## 2. 产品形态：侧栏多一页「任务」

- 列表一屏看完：名称、状态徽标（运行中 / 已停止 / 重启中 / 失败）、PID、已运行时长、重启次数、健康检查结果、日志大小。
- 每行三个按钮：启动 / 停止 / 重启，末尾「日志」和「编辑」。
- 顶部：「新建」（JSON 编辑器，带模板下拉）、「全部停止」、「打开日志目录」。
- 开关：**随程序启动**（默认开）—— VPNTray 自启 → 托管任务跟着起来，用户什么都不用做。
- 托盘菜单加一项「托管任务：N 个运行中」→ 点开控制台的任务页。

**唯一新增的心智负担**：任务不是模块。模块是「域名 → 出口」的规则，任务是「一个进程」。两者放在不同页，互不干扰。

---

## 3. 数据模型：`data/tasks/<key>.json`

沿用模块的约定（一文件一对象、key 即文件名、原子写、不改用户数据），字段如下：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `schema` | int | 1 | 结构版本 |
| `key` | str | — | `^[a-z0-9][a-z0-9_-]{1,31}$`，文件名同 key |
| `title` | str | — | 界面显示名 |
| `desc` | str | "" | 一句话说明（AI 写的任务尤其需要） |
| `cmd` | list[str] | — | argv 数组，**不经过 shell**（避免引号地狱与注入） |
| `cwd` | str | `{data}` | 工作目录，支持占位符 |
| `env` | dict | {} | 追加环境变量（不覆盖系统关键项，见 §7） |
| `autostart` | bool | true | 随 VPNTray 启动 |
| `restart` | str | `on-failure` | `always` / `on-failure` / `never` |
| `max_restarts` | int | 20 | 一小时内超过即判失败（防「疯狂重启」把 CPU 打满） |
| `stop_timeout` | int | 8 | 先 terminate，超时后 `taskkill /T /F`（秒） |
| `health` | obj | `{"type":"none"}` | `none` / `http`（url，2xx/3xx 算健康） / `tcp`（host,port） |
| `health_interval` | int | 30 | 健康检查间隔（秒） |
| `restart_on_unhealthy` | bool | false | 连续 3 次不健康时是否重启（默认只告警，不擅杀） |
| `log_max_mb` | int | 8 | 单任务日志上限，超过轮转一份 `.1` |
| `enabled` | bool | true | 关掉 = 不随程序启动，也不许自动重启 |
| `note` | str | "" | 给用户看的备注（谁写的、干什么用的） |

占位符（避免硬编码路径）：`{data}` → `data/`、`{logs}` → `data/logs/`、`{tasks}` → `data/tasks/`、`{app}` → 程序根目录、`{home}` → 用户目录。

解释器解析（顺序固定，失败就明确报错，不猜）：
1. 命令是绝对路径且存在 → 直接用；
2. `python` / `python3` → `settings.tasks_python` → PATH 里的 `python.exe` / `py.exe`；
3. `node` → `settings.tasks_node` → PATH；
4. 其它裸名 → PATH（`shutil.which`）。

> 打包后的 VPNTray 自带 Python 运行时，但**不提供** `python.exe` 给外部用（PyInstaller 的运行时是嵌在 exe 里的）。所以任务用 Python 时依赖用户机器上的 Python，找不到就在界面直接写「没找到 python，请装 3.10+ 或在设置里指定路径」，不要让任务静默失败。

## 4. 状态机与重启策略

```
stopped ──start()──> starting ──进程起来──> running
   ^                    │                    │
   │                    └─起不来─> failed <──┴─退出码≠0 且 restart=on-failure/always
   │                                    │
   └──────── stop() ────────────────────┴─> backoff ──到点──> starting
```

- **backoff**：5s → 10s → 30s → 60s → 300s（封顶），任一时刻「稳定运行超过 60 秒」就把计数清零（避免「跑一次崩一次」被判成失败后永不再试）。
- **失败判定**：一小时内重启次数 > `max_restarts` → `failed`，不再自动重启，托盘通知一次（这条最重要：否则一个崩溃循环会把机器拖死）。
- **手动操作优先**：用户点「停止」后即使 `restart=always` 也不再拉起（记 `user_stopped` 标志，直到用户再点启动）。
- **退出程序**：默认 `taskkill /T /F` 结束整棵进程树（它们是我们的子进程，不能留孤儿）。「我退出但守护继续跑」明确不做 —— 那等于变相注册服务，和「一切在软件内」的原则冲突。
- **崩溃取证**：每次非零退出记 `last_exit` / `last_error`（stderr 最后 20 行）到状态里，界面上直接显示，不用翻日志。

## 5. 进程与日志

- `subprocess.Popen(argv, cwd=…, env=…, stdout=<log>, stderr=STDOUT, creationflags=CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP, stdin=DEVNULL)`
- **不用 shell**：命令是数组，杜绝 `& whoami` 这类注入；也确实不需要管道。
- 日志写 `data/logs/tasks/<key>.log`，UTF-8 强制（`PYTHONIOENCODING=utf-8`、`PYTHONUNBUFFERED=1`），读日志时容错解码（`errors="replace"`）。
- 轮转：超过 `log_max_mb` → 关句柄、`.log` → `.log.1`（覆盖旧的 `.1`）、重开。只留一份历史，够用且不会吃满盘。
- 结束进程树用 `taskkill /PID <pid> /T /F`：Python 的 `terminate()` 在 Windows 上只杀直接子进程，脚本里再 `subprocess` 起的子进程会变孤儿（这是最常见的「端口一直被占」来源）。
- 状态里给 `uptime`、`pid`、`restarts`、`last_exit`、`health`、`log_size`，由 supervisor 线程每 2 秒刷新，不做「点一下才刷新」。

## 6. 接口层

### 6.1 HTTP

| 路由 | 作用 |
|---|---|
| `GET/POST /api/tasks` | 列表 + 每个任务的运行状态 |
| `POST /api/task/get` | 取原始 JSON（编辑用） |
| `POST /api/task/save` | 新建 / 更新（校验失败返回逐条错误） |
| `POST /api/task/delete` | 先停再删（含日志可选删） |
| `POST /api/task/start` / `stop` / `restart` | 生命周期（`sync=true` 可等结果） |
| `POST /api/task/log` | 尾部 N 行（默认 200，最大 2000） |
| `POST /api/task/clear-log` | 清空 |

`/api/state` 增加 `state.tasks`（列表 + 汇总：运行中 N / 失败 M）。

### 6.2 AI 工具（`/ai/v1`）

| 工具 | 级别 | 说明 |
|---|---|---|
| `tasks.list` / `tasks.status` | read | 列表与运行状态（AI 判断「我上一步写的守护起没起来」） |
| `tasks.get` / `tasks.log` | read | 原始 JSON / 日志尾部（AI 自己排错） |
| `tasks.save` | write | 新建或更新（**必须带 title 与 desc**，否则拒绝 —— 防 AI 写一堆无名任务） |
| `tasks.start` / `tasks.stop` / `tasks.restart` | write | 生命周期 |
| `tasks.delete` | write | 删除（带 confirm 参数，防误删） |

AI 的完整工作流一句话跑通：

> 用户：「帮我写个程序，每分钟看一眼某目录，有新文件就调这个接口。」
> AI：`tasks.save({key:"watch-inbox", title:"盯收件目录", desc:"…", cmd:["python","{tasks}/watch-inbox/main.py"], cwd:"{tasks}", autostart:true, restart:"on-failure"})` → `tasks.start` → `tasks.log` 确认没有 traceback。

## 7. 安全边界（这一节决定了这个功能能不能做）

**本质**：这是「给 AI 一个开机自启的代码执行位」。必须按这个严重程度对待。

1. **权限门**：`tasks.save` / `start` / `delete` 属于 `write` 级，受 `ai_api_level` 限制；`read` 级别只能看。
2. **每次创建都出声**：新建任务时托盘弹一次通知「AI 新建了托管任务：<标题>（<命令第一项>）」，任务卡标 `来源: AI`。绝不静默落盘。
3. **拒绝清单**（写了直接报错）：
   - `cmd` 首项命中：`format`、`diskpart`、`bcdedit`、`reg delete`、`shutdown`、`sc` 的写操作；
   - 参数出现 `rm -rf /`、`--no-preserve-root` 这类自毁模式；
   - `cwd` 落在系统目录（`C:\\Windows`、`Program Files`）；
   - `env` 试图改 `PATH`（会让后续任务解析错乱）。
4. **不接管系统服务**：不做 `sc create`、不装驱动、不注册计划任务，一切都在进程树内。
5. **资源上限**：最多 16 个任务、单任务日志 8MB、重启风暴有闸；CPU/内存不设硬限（会误杀正常任务），但状态里显示占用，超 500MB 标黄。
6. **可审计**：`data/tasks/<key>.json` 明文，用户在文件管理器里就能看到 AI 到底写了什么；每次启动/停止写一行 app.log。

## 10. 分三步实施

| 步骤 | 内容 | 产出 | 估时 |
|---|---|---|---|
| A 最小可用 | `tasks.py`（注册表 + 启动/停止 + 自动重启 + 日志）、4 条路由、任务页列表、开机拉起 | 能用：AI 存一个任务，重启电脑它回来 | 1.5 天 |
| B 可观测 | 健康检查（http/tcp）、崩溃计数与失败态、日志轮转、托盘通知、日志查看器 | 出事能自己看出为什么 | 1 天 |
| C AI 与模板 | 7 个 AI 工具、四个模板、`来源:AI` 标记、危险命令拒绝清单 | AI 一句话建任务 | 0.5 天 |
| D 打磨（可选） | 更新前暂停/恢复、任务依赖模块、内存占用高亮 | — | 0.5 天 |

合计约 **3.5 天**；A 做完就已经解决「AI 写的守护程序没地方放」这个原始诉求。

## 11. 风险清单

| 风险 | 影响 | 处理 |
|---|---|---|
| AI 写入恶意/错误命令 | 高 | 拒绝清单 + 托盘通知 + 明文 JSON 可审计 + 只写不降权 |
| 崩溃循环拖死机器 | 高 | `max_restarts`/小时 + 背退避 + 稳定 60s 清零 |
| 子进程变孤儿占端口 | 中 | `taskkill /T /F` 结束整棵树 |
| 日志写爆磁盘 | 中 | 单任务 8MB 轮转 + 上限 16 个任务 |
| 用户删了 data 目录 | 低 | 定义在 data 里，删了就没了 —— 和模块一致，界面提示 |
| 更新时 exe 被占用 | 中 | 更新流程先 `stop_all()`，替换后恢复 |
| 杀软对「自启 + 常驻子进程」敏感 | 中 | 不写注册表启动项、不注册服务、子进程隐藏窗口 |

## 12. 验收标准

1. `tasks.save` 一个 Python 循环脚本 → `tasks.start` → `state.tasks` 里 `running`、pid 有值；
2. 手动 kill 那个 pid → 30 秒内自动重启，`restarts` +1，日志里有 `[supervisor] 进程退出 code=...`；
3. 让它每秒崩一次 → 达到 `max_restarts` 后变 `failed` 且不再重启，托盘只通知一次；
4. 重启 VPNTray → `autostart` 任务自动回来，`user_stopped` 的不回来；
5. 退出 VPNTray → 任务进程树全部消失（`tasklist` 里没有残留）；
6. `tasks.save` 传 `cmd:["cmd","/c","del /s /q C:\\*"]` → 明确拒绝并说明原因；
7. 日志到 8MB → 轮转出 `.log.1`，新日志继续写，界面不卡。

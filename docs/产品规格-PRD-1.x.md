# VPNTray 产品规格（PRD）· 1.x 线

> 版本：v1（2026-11-14）　基线：VPNTray 1.0.1　主体：个人开发者 ayuanjc@gmail.com
> 一句话：**代理是主干，诊断是骨架；每个结论都要有证据，每个修复都要能撤销。**

---

## 0. 已锁定的产品决定（不再讨论，除非推翻重来）

| # | 决定 | 推出的硬约束 |
|---|---|---|
| 1 | 主身份是**医生**：说清问题、修好、验证 | 任何功能上线前先问：它是「说清/修好/验证」，还是「许诺更快」？后者砍 |
| 2 | **不做**「彻底优化」（不关更新、不删组件、不清注册表、不装驱动） | 只碰网络子系统；优化只做 MTU / DNS / 出口 / IPv6 / 代理路径五件 |
| 3 | 优化必须**前后对比** | 没有「改前数字 / 改后数字」的功能不上线 |
| 4 | **代理是主干，不能因为做诊断而弱化** | 概览页首屏与托盘菜单永远保留：连接状态、节点切换、系统代理开关、模式切换。诊断只能放在它们**之后**，不能挤走 |
| 5 | 用户能选**看见什么**（三档显示级别）与**用什么词**（白话/术语） | 需要统一的文案层，界面只引用 key |
| 6 | 分发：**绿色版**、**只有中文**、**无账号**、**赞助制** | 不加 license 校验、不做云同步、不做安装包（暂） |
| 7 | 数据：**默认分享、只上传聚合指标** | 上线前必须有可查看/可导出/可删除的界面 |
| 8 | 诊断规则**开放**（用户与 AI 都能写 pack） | pack 是数据不是代码，格式要稳定、可校验 |

## 1. 用户与场景

| 用户 | 他要什么 | 我们的答法 |
|---|---|---|
| 主人（你自己） | 一切可控、一切可见、能命令行/AI 操作 | 专业级别 + AI 接口 + 开放 pack |
| 朋友/同学 | 「我的网/我的 AI 又不行了」，不想学 | 简洁级别：一句结论 + 一个按钮 |
| 未来的外部用户 | 不想装 360，也不想看文档 | 首次引导 3 屏 + 报告可分享 |

**核心场景（按频次）**
1. AI 工具报错看不懂（最高频、最痛、现在完全无解）；
2. 某个网站/游戏/Xbox 打不开（已有 13 项体检）；
3. 慢、卡、掉线（路径质量，未做）；
4. 换环境要重配（校园网/公司/家里，已有一半）；
5. 想确认「我的网络到底健不健康」（体检报告，未做）。

## 2. 信息架构

```
概览    ← 代理控制第一屏（连接状态 / 出口 / 流量 / 节点快切 / 系统代理）
节点    ← 列表 + 延迟 + 纯净度 + 自动优选
场景    ← 域名→出口的模块（含 Xbox/游戏平台/OCR 等）
诊断    ← 新：健康卡 + 八个域 + 事件时间线 + 报告（原「扩展」页并入）
  ├ 链路（连通性 / 路径质量 / MTU / IPv6）
  ├ 解析（DNS 体检 / 投毒 / 优选）
  ├ 出口（节点质量 / 应用级走向）
  ├ API（API 医生）
  └ 修复历史（动作 + 撤销）
AI      ← AI 通道 / AI 接口 / OCR 桥（1.0.1 已独立）
订阅    ← 订阅管理
设置    ← 分组 + 显示级别 + 文案风格 + 数据共享 + 隐私/用户协议
```

托盘菜单保持现状（代理相关在最前），诊断只加一条「跑一遍体检」。

## 3. 文案层（决定「用户能选看见什么」能不能做成）

**结构**：`data/copy/zh-CN.json`（可被用户覆盖，内置一份同名默认值）

```json
{
  "schema": 1,
  "diag.dns.poison.title": { "plain": "有人把你的域名解析指到了假地址", "term": "DNS 投毒（返回黑洞地址）" },
  "diag.dns.poison.why":   { "plain": "…", "term": "…" },
  "diag.dns.poison.fix":   { "plain": "换个更稳的解析", "term": "切换至 DoH 上游" }
}
```

**三档显示级别**（设置项 `ui_level`，全局生效）

| 级别 | 展示内容 | 默认给谁 |
|---|---|---|
| 简洁 `simple` | 结论 + 主按钮 | 家人/同学 |
| 标准 `normal` | 结论 + 证据（2–3 行）+ 动作 | 默认 |
| 专业 `pro` | 再加：原始报错、request-id、时间线、命令、pack id | 你自己 |

**规则**：界面上任何面向用户的句子都不得硬编码中文；新增功能必须同时提交 key。
> 现状：全项目散落的中文字符串约 1000+ 条，不要求一次搬完；新代码必须走 layer，旧代码按域逐步迁。

## 4. 诊断内核：事件 → 指纹 → 动作

这是整个软件后续所有「域」的公共骨架（DNS、路由、Xbox、校园网、API 都用它）。

```
  采集（事件）        匹配（指纹）           处置（动作）            验证（复测）
  ─────────────      ─────────────       ──────────────      ────────────
  代理层/网关/探针/粘贴 → pack 指纹 → 候选动作（可撤销） → 重新探一次
        │                  │                   │                  │
        └──── 事件表 ────────┴─── 动作表 ─────────┴──── 报告/时间线 ──┘
```

**事件**（`data/diag/events.jsonl`，追加写、可轮转）
`ts / domain / provider / category(A|B|C) / fingerprint_id / status / ms / exit_ip / node / request_id / snippet(脱敏 200 字) / source(proxy|gateway|paste|probe)`

**动作**（`data/diag/actions.jsonl`）
`ts / action_id / event_id / before / after / result / verify(status,ms) / by(user|ai) / undone`

**pack**（`data/packs/<key>.json`，用户与 AI 可写）

```json
{
  "schema": 1,
  "key": "api-doctor",
  "title": "API 报错诊断包",
  "fingerprints": [
    {
      "id": "api.auth.invalid_key",
      "category": "A",
      "match": { "provider": ["deepseek", "openai", "anthropic", "qwen"], "status": [401], "body_re": "invalid.?api.?key|Incorrect API key|authentication_error" },
      "title_key": "api.auth.invalid_key.title",
      "actions": ["switch_key", "open_key_page", "copy_request_id"]
    }
  ]
}
```

**动作注册表**（内置 10 个，全部可撤销；每个都有 `before/after` 快照）

| id | 做什么 | 可撤销 | 需要管理员 |
|---|---|---|---|
| `flush_dns` | 清 DNS 缓存 | 不需要（无副作用） | 否 |
| `fix_proxy` | 清掉系统代理残留 / 重设到 7891 | 是（还原原值） | 否 |
| `switch_node` | 切到指定节点 | 是 | 否 |
| `restart_kernel` | 重启内核 | — | 否 |
| `clock_sync` | 重新对时（w32time） | 不需要 | 是 |
| `set_dns` | 切系统 DNS 到候选值 | 是 | 是 |
| `set_mtu` | 改 MTU | 是 | 是 |
| `start_dns_guard` | 起本机 DNS 兜底 | 是（关掉） | 否 |
| `clean_hosts` | 备份后修复 hosts | 是（有备份） | 是 |
| `disable_ipv6` | 关掉半死 IPv6 | 是 | 是 |

## 5. API 医生（第一个 pack）

### 5.1 三个捕获入口

| 入口 | 看得到 | 覆盖 | 代价 |
|---|---|---|---|
| 代理层静默记录 | 域名、时刻、成功/失败、耗时、出口 IP | 所有走系统代理的程序 | 零（数据已在手） |
| 本地网关（可选，127.0.0.1:8787） | 状态码、错误体、request-id、用量 | 把 base_url 指过来的程序 | 改一行配置 |
| 粘贴 / 从日志抓 | 用户看到的那段文本 | 一切 | 指纹库要够聪明 |

**明确不做**：HTTPS 中间人（MITM）。原因：要装根证书、杀软报警、银行类应用拒绝连接、卸载残留——与「网络管家」的信任定位冲突。

### 5.2 四家 provider 的差异（指纹按 provider 分，不按状态码硬套）

| provider | 认证 | 错误体形状 | 高频坑 |
|---|---|---|---|
| DeepSeek | `Authorization: Bearer` | `{"error":{"message","type"}}` | 余额不足常写在 message；reasoner 参数不兼容会 400 |
| DashScope(qwen) | `Bearer` / `?api_key=` | `{"code","message","request_id"}`，**HTTP 可能仍是 200** | `Arrearage` / `InsufficientBalance`；模型名要带前缀 |
| OpenAI 兼容自建 | 自定义 | OpenAI 形状 / 纯文本 500 / HTML | `model not found` 实为后端未加载；one-api 分组权限文案 |
| Anthropic | `x-api-key` + `anthropic-version` | `{"type":"error","error":{"type","message"}}` | 缺 version 头 400；`max_tokens` 必填；区域/密钥类型两套 |

### 5.3 三行文案（硬规范）

> **结论**：谁的问题，一句话，≤30 字。
> **证据**：必须是可核对的事实（状态码 / 数值 / 地址 / 耗时）。禁止「可能」「建议检查」。
> **动作**：1–3 个按钮，每个都标注「会改什么 · 可撤销」。

例：
> 结论：key 没过期，是这个节点的 IP 被上游限流了。
> 证据：HTTP 429；同一 key 走 香港-优化3 三次全 429，换 日本-优化1 立即 200（0.9s）。
> 动作：[切到 日本-优化1 · 可撤销] [记住这个组合] [看详细]

### 5.4 本地偏好记忆（不联网）
同一指纹下，用户选了某动作且复测成功 → 记一次；累计 ≥3 次 → 该动作排第一并标「你上次是这么修好的」。纯本地，不上传。

### 5.5 探针
只在用户点「诊断」时发一次最小请求（最便宜模型、1 token）；不后台定时跑；不自动重试到成功（会掩盖问题、放大计费）。

### 5.6 给 AI 用
新增 AI 工具：`api.diagnose`（read，返回结构化结论）、`api.events`（read）、`api.actions`（read）、`api.fix`（full，需确认）。
意义：AI 报错时直接问本机，不用让用户复制粘贴。

## 6. 数据与隐私

**不上传**：API key、prompt、响应内容、域名原文、内网 IP、文件路径、任何可定位个人的信息。
**上传（聚合，每日一次）**：provider 分类、错误类别、状态码分布、延迟分桶、省份 + ISP + 时段、节点地区。
**界面必须有**：看（明文 JSON）/ 导出 / 清空 / 关闭。
**协议**：
- 《用户协议》：软件按现状提供、无担保、不承担因误用导致的损失；不提供绕过法律法规用途；版本与变更通知方式。
- 《隐私协议》：说明上述字段、目的（改进诊断准确率）、保存期限（建议 90 天）、行使权利的方式（导出/删除/关闭）、联系方式 ayuanjc@gmail.com、适用法律（中国大陆）。
- 首次启动单独一栏「网络质量数据」勾选（默认勾选，可取消），与总协议分开。

## 7. 路线（七域 + 四期）

| 期 | 内容 | 与代理的关系 |
|---|---|---|
| **1.1** | 诊断内核（事件/指纹/动作/复测）+ API 医生 + 诊断页框架 + 文案层 v0 | 只读代理数据，不改代理行为 |
| **1.2** | 健康卡（首屏结论）+ DNS 域（体检/优选/DoH）+ 报告导出（HTML） | 复用现有 dnsguard |
| **1.3** | 路径质量（逐跳）+ 应用级走向（进程→规则→出口）+ 时间/证书检查 | 需要内核 API 的 connections |
| **1.4** | 托管任务（AI 写的守护程序）+ 探针模板 + 聚合数据上传 | 任务可托管探针 |
| 2.0 | 网络环境档案（按 SSID/网关切换）+ 动作目录平台化 + 局域网 | 与场景模块打通 |

**每期都保持**：概览页第一屏是代理控制；诊断入口在其后。

## 8. 验收标准（1.1 结束时）

1. 粘贴一条 401 → 3 秒内出三行结论，动作可点，点完复测显示新状态码；
2. 走系统代理的 AI 工具失败 → 代理层记一条事件（域名+失败+耗时），API 医生时间线可见；
3. 429 场景：切节点后复测 200，动作历史里可撤销并回到原节点；
4. 三档显示级别切换后，同一条事件在简洁/标准/专业下呈现不同（且专业级能看到 request-id）；
5. 白话/术语切换生效，且不刷新页面；
6. `data/packs/*.json` 放进一条自定义指纹 → 无需改代码即生效；
7. 协议页可打开、可查看「我上传了什么」、可一键关闭上传；
8. AI 调 `api.diagnose` 返回结构化结论（category/fingerprint/evidence/actions）。

## 9. 不做清单（写进 README，避免自吹）

- HTTPS 中间人解密；
- 注册表清理、关更新、删预装、装驱动、注册系统服务；
- 自动重试到成功、自动轮 key 池；
- 代改用户业务代码（只给建议与可复制片段）；
- 云账号、云同步、在线指纹库；
- 「一键优化 137 项」这类不可归因的承诺。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 诊断把代理挤成配角（用户最担心） | 概览首屏与托盘菜单优先级写进验收；任何改版先过这一条 |
| 误修 | 每个动作有 before 快照 + 十分钟内可撤销 + 复测 |
| 隐私质疑 | 只上传 9 个聚合字段，界面可查可删，协议写明主体与联系方式 |
| 指纹库维护成本 | pack 开放 + 兜底「这条没见过」+ 一键复制成可提交报告 |
| 文案两套走形 | 单一 copy 源 + key 校验（缺 key 直接报错，开发期就暴露） |
| 范围膨胀 | 每期只做一个域，做完发版；未进 PRD 的功能一律不做 |
